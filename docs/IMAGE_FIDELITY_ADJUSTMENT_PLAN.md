# 图鸣 · 图像忠实性与自适应音乐复杂度调整计划

日期：2026-10-06（北京时间）

基线：PixelMusic 0.5.0

作曲版本：0.6.0，参数已在本轮测试集与扫描中固定

状态：0.6 已实现并完成验收。自动验证与 HTTP 运行检查通过，用户于 2026-10-07 手动确认直接 HTML 的生成、播放、高亮、区域试听与 WAV 保存均正常。不发布在线预览。详见 [实现报告](./FIDELITY_IMPLEMENTATION_REPORT.md)。以下保留原计划与验收要求，计划中的“待实施”描述属于设计历史。

## 1. 本轮目标与核心取舍

**图片提供多少变化，音乐就表达多少变化。音乐规则整理图片给出的变化，不凭空补出一首曲子。**

用户已认可这个方向：纯白、纯灰等低信息图片应产生单纯、重复或静态的声音，而不是被强行补成有高潮、有和弦进行的完整旋律。

下一版优先级调整为：

1. 图像来源可信：重要的音乐变化能解释其图片依据。
2. 相同输入可复现：不随机补音、不用图片哈希挑选曲子。
3. 在前两项内保持可听性：平滑连接、合理音域、温和音色和收尾。

不再要求所有图片都像一首歌曲。纯色图可以是一段稳定声景，复杂图才有更多发展。这里的像素与声音关系是产品选定的艺术映射，不是“白色客观上等于某个音符”。

## 2. 0.5 纯白图为什么仍有旋律

当前纯白规范化像素为 `RGB(255,255,255)`：亮度 1，饱和度、边缘、空间活动度均为 0。现有诊断生成 C 调柔和大调、基础速度 76 BPM、120 个主旋律事件，含尾音约 52.72 秒；前七音为 `C4 → F4 → F4 → E4 → E4 → G4 → A4`。

图片本身没有提供这些高低起伏。主要补全来源在 `dist/music.js`：

| 当前来源 | 对纯白图的影响 | 下一版处理 |
| --- | --- | --- |
| `makeTheme()` 默认拱形轮廓 | 相同区域也有先上行再回落的目标 | 由特征序列生成轮廓；恒定输入得到平直轮廓 |
| 行号音高偏移、每五音固定装饰 | 同色区域因位置和序号而产生变化 | 移除无图片依据的固定偏移 |
| 第三乐句抬高、固定高潮 | 无转折的图仍必有高潮 | 取消必有高潮；显著落点由真实转折决定 |
| 固定句首／句尾音高目标 | 每句都被拉回预设路线 | 只保留包络收尾，不强制跳到主音或属音 |
| 预设和声进行、重复音惩罚 | 和声推动旋律；稳定音被当成缺点 | 允许同音持续；伴奏不能反向制造图中不存在的运动 |
| 每区域必须独立起音、每小节 6–9 音 | 缺少变化仍被迫持续敲击 | 区域身份与实际起音分离，允许跨区域连音 |
| 四句固定力度弧线与速度呼吸 | 静态图也自动起伏 | 低信息输入关闭内部表达弧线，只保留起止淡入淡出 |

这是生成目标与数据结构的调整，不是给“纯白图片”加一个文件类型或颜色特判。

## 3. 保留与放开的约定

保留：

- 图片在浏览器本机处理，不使用语义识别、AI 音乐模型或在线音源。
- 192×120 规范化像素、24 列 × 5 行的 120 个区域，沿现有蛇形顺序读取。
- 120 个区域全部可追溯、可点击试听；声音可以相同，出处不能丢失。
- 三种用户选定音色、本地 HTML、播放进度、高亮、切换音色与 WAV 保存。
- 同一规范化像素、算法版本及设置复现相同乐谱。

放开：

- 不再要求 120 次独立起音。首版主旋律起音可为 1–120 次，由图像结构决定。
- 不再要求每小节 6–9 音、每句 30 个发声事件、至少四种音高、一个唯一高潮或最终回到主音。
- 相同声音可以跨区域、跨小节、跨原乐句边界持续；不能仅为过小节重新起音。
- 四段位置可以用于导航，但不再等于四段必须发生的音乐剧情。
- 节奏、表达及伴奏可以简单，不能为了指纹种类多而制造变化。

**“每个区域都有声音身份”不等于“每个区域必须有不同音高”，也不等于“每个区域都要敲一下”。**

首轮仍保留 64 拍及现有总时间轴，16 小节仅作为时间参考。这可限制改造范围、保留完整扫描。纯白图因此可能是一段接近 50 秒的持续音，这是明确的长度取舍；诊断时可截取前 10–16 秒。按信息量缩短全曲可后续单独设计，不通过重新敲击来让长音“热闹起来”。

## 4. 图像信息量：看结构，不看“颜色多不多”

### 4.1 输入特征

复用 0.5 的亮度、饱和度、饱和度加权色相、平滑后的横纵变化、纹理组织度、周期性和稳定区统计。需要时在当前 4×4 平滑之外补充固定尺度的对照，以区别有组织的细纹理和独立像素噪声。

分别保留：

- 绝对特征：颜色与亮度，决定基本音高／音域或小幅声音参数。
- 局部差异：相邻区域变化、累积漂移、结构边界，决定音乐何时改变。
- 组织特征：方向、周期与重复边缘，决定有依据的重复起音和节奏分组。
- 全局与局部复杂度：全局用于摘要、速度和伴奏预算；局部用于自己的声音变化。

同一色相遍布全图，不能因为饱和度很高就产生大量旋律变化。噪声的颜色熵很高，也不能直接当成丰富音乐的依据。

### 4.2 连续复杂度，而不是三套新模板

形成归一化 `C_global` 与 `C_local[i]`，均在 0–1 内。初始可考虑：

```text
C = clamp(0.50 × 平滑空间变化
        + 0.35 × 有组织纹理
        + 0.15 × 周期性 × 空间变化, 0, 1)
```

权重与归一化尺度是待校准起点，不是已验证最优值。最终参数在扩展集上校准后固化到版本，不随上传历史或当前测试批次变化。

硬要求：恒定颜色的空间复杂度必须为 0，无论它是白、黑、灰还是鲜红；小噪声经过固定容差后应保持接近 0。周期性不能把无边缘的恒定场提升为复杂图。

复杂度控制可使用的变化幅度、伴奏和表达预算，不指定“必须生成 N 个音”。明显的小色块不能被全图平均复杂度低这一事实抹掉；实际变化仍由局部证据驱动。

## 5. 音高：相同特征得到相同目标

### 5.1 基础映射与变化映射分离

先从可靠的颜色统计选择一个固定音阶／音高参考，亮度等绝对特征决定各区域的基础目标；灰阶没有可靠色相时使用明确的中性参考，不从哈希补一个调。

相同区域特征、相同全局设置，必须得到相同基础目标。区域行号、列号和序号只用于定位及读取顺序，不作为额外音高花纹。

`localSeed` 或局部像素哈希也不能用来给相同可听特征偷偷挑选不同音符；并列决策使用固定顺序。图像摘要留作身份与校验，不承担补全旋律的职责。

具体音域、亮度映射和量化阈值在实施时比较并冻结，本文不提前指定“白色必须是哪一个音”。纯白的硬要求是稳定单音，不是某个音名。

### 5.2 从像素轨迹生成轮廓

- 移除默认 `arch / rising / falling / wave` 形状对旋律的强制填充，转为从实际区域目标形成轮廓。
- 平滑亮度渐变允许量化后的阶梯上行／下行与平台，不插入预设拱形或固定回头。
- 大块转折可以带来明确变化；重复结构可以复现对应动机。
- 取消“重复越多越差”的普遍惩罚：相同区域保持相同声音应是正确结果。
- 没有图片依据，不抬高第三段、不制造唯一最高音、不强制每句改变起音或落音。

音阶量化、合理音域和连接平滑仍保留。它们可以压缩过大的跳进或折叠八度，但不为满足旧连接音规则插入无区域出处的额外音符；记录量化／平滑改变了什么。

亮度、色相等映射会有量化平台。接近的图片可以拥有相同音高和节奏，不用随机种子强行分开，也不把只改摘要字符当作可听差异。

## 6. 相邻区域如何变成一个长音

### 6.1 合并依据

先建立每个区域的声音目标及图像边界证据，再按读取顺序建立持续片段。允许合并须同时满足：

1. 音高目标一致，声音参数一致或在固定容差内可连续过渡。
2. 没有超过阈值的真实颜色／结构边界。
3. 没有被测出的有组织纹理要求在此重新起音。
4. 与片段起点的累积特征差异仍在容差内，而不只比较相邻两个区域。

第四项防止“渐变每步很小，所以整张渐变图也被合并成纯色长音”。阈值判断来自当前输入及固定规则，不引入跨上传状态的迟滞。

合并只影响音频事件，不删除、跳过或重排区域。区域单独试听仍有确定映射。

### 6.2 同音高不一定必须合并

条纹或棋盘即使各区域平均色相同，内部仍可能有可测的重复边缘。其周期、方向和相位可以映射成同音高的重复起音；诊断记录“图像周期 → 起音分组”的依据。

不能只靠平均颜色或量化后的 MIDI 判断合并，否则会把有组织的纹理也压成纯色。也不能仅因“隔了五个区域”或“到了下一小节”重新起音。

首版将重触发约束在区域边界，并保持每个区域至多支持一次主旋律起音，避免同时引入区域内部多音采样的新范围。静态图没有这样的重触发依据，应合并为一个事件。

## 7. 节奏与时间预算重新分配

顺序改为：区域目标／结构证据 → 持续片段与有依据的重触发 → 片段时间预算 → 发声事件，不再先塞满 120 个音再改长短。

- 整曲首轮仍分配 64 拍；实际起音和显式休止使用现有 0.25 拍网格。
- 片段预算考虑覆盖区域数、稳定程度和显著落点；稳定片段可以持续多小节。
- 合并片段内部再分配区域访问时间，内部访问边界只是动画时间，不是新的起音。
- 起音密度跟随结构；保留对持续碎音和突兀节奏的限制，但取消每小节最低音符数及 1.5 拍最大名义音长等旧假设。
- 休止必须有结构依据，或明确属于作品起止处理；不把所有稳定区域解释成“空白”，也不固定每句停顿。
- 基础速度仍可使用图片活动度；纯白无内部活动，不使用固定句间呼吸或末段变速来补出运动。收尾由音量包络完成即可。

两个时间事实必须分开：扫描可以经过 120 个区域，音频却只起音一次。不能用固定扫描速度形成的 120 个时间格，冒充图片生成了 120 个节拍。

## 8. 数据结构：区域与声音事件成为两层

建议保留 `melody` 字段作为实际主旋律发声事件数组，长度可变；新增 `regionMap` 保存全部区域。音频排程只读实际事件，不能同时把 120 个区域再排程一遍。

| 数据 | 职责 | 关键字段建议 |
| --- | --- | --- |
| `regionMap[120]` | 区域身份、访问时间、点击试听、反向查找 | `regionId`、`sequence`、`startBeat`、`endBeat`、`voiceEventId`、`previewRef` |
| `melody[1..120]` | 实际起音、持续与声音参数 | `id`、`beat`、`beats`、`durationBeats`、`midi`、`regionIds`、`envelope`、`featureSupport` |
| `bassEvents / padEvents` | 有依据的可选伴奏 | 沿用显式事件；允许为空 |
| `diagnostics` | 说明为什么变化或合并 | 复杂度、边界证据、合并范围、周期重触发、量化／平滑原因与决策余量 |

纯白的目标示意：120 个 `regionMap` 项按时间连续覆盖全图，全部引用同一个持续声音事件；`melody` 只有一个事件，跨越整段访问过程，结束时释放。这里的“一次起音”指主声部事件，不是合成器内部谐波振荡器的数量。

一般图片若有显式休止，休止区间独立记录，不伪造一个区域或音符去填满。区域访问区间与休止共同解释整段时间；休止时暂停访问高亮或显示最近访问区域及休止状态。纯白没有内部休止，因此区域访问本身连续覆盖全部 64 拍。

指纹同时拆分：

- 图像指纹：规范化像素身份。
- 映射指纹：120 个区域如何关联声音及访问时间。
- 节奏指纹：**实际发声事件**的起音、名义时值和显式休止，不包含 120 个扫描格。
- 表达／完整乐谱指纹：包含实际持续、包络、伴奏、速度时间轴及版本设置。

实际发声谱完全相同就允许声音指纹相同。不同像素可以有不同图像指纹，但相同音乐，不做“每图必须不同”的假承诺。

## 9. 伴奏和演奏表达同步收敛

### 9.1 伴奏

纯白及其他恒定颜色的默认作品仅有主声部：低音、铺底事件为空，不循环预设和弦进行。

有结构的图片可启用稀疏伴奏，但和声改变必须响应局部音高／色彩组织，而不是照搬固定 16 小节路线。已有平滑转位和合理低音音域可复用，和声应适配图片旋律，而非迫使图片旋律服从预设进行。

全局复杂度连续调节伴奏预算，不用低／中／高三档各播放一套新模板。没有结构边界，不得仅因跨小节或跨导航段换和弦。

### 9.2 长音包络

播放器需要支持真正的持续音：温和起音、稳定保持、最终释放。不能用大量短音重叠伪装长音，也不能在每个区域重新触发包络。

- 静态片段保持稳定的音高与内部力度；用户选择的音色保持不变。
- 小幅声音参数过渡只能来自可追溯的图像变化，不加随机漂移、固定震音或四句力度弧线来“丰富”纯色图。
- 区域点击试听截取对应声音的短包络，不播放整段 50 秒长音；明确这是局部试听，不是另一套作曲。
- 中途切换音色，在当前持续事件的位置接续并短交叉淡化，不从作品开头或当前长音最初的攻击阶段重放。
- 实时播放、扫描、续播、离线 WAV 都使用现有统一时间轴；停止后清理持续源与回声节点。

不能把“黑色”默认解释成静音。纯黑同样是有效颜色输入，应有可听的稳定声音，具体音域和力度由固定映射决定。

## 10. 页面与交互调整

- “120 音”改为“120 个区域 · N 次起音”，另显示时长；纯白显示一次起音，不继续暗示它有 120 个不同音。
- `playbackPosition()` 分别返回当前区域位置与实际声音事件位置，不再用 `melody[index]` 同时代表两者。
- 长音内部高亮按 `regionMap` 继续经过所有区域，不能停在第一个区域，也不能把高亮变化当作再次发声。
- 区域点击通过 `previewRef / voiceEventId` 读取同一映射的音高和材质；纯白各区域试听相同是正确结果。
- 长音中声音参数若缓慢变化，局部试听取区域访问时刻的参数，不另造一个音。
- 导航可保留四段图像位置，改称中性段落；不标注尚不存在的“发展”或“高潮”。
- 更新算法版本、规则说明及指纹语义，明确“相同声音可以关联多个区域”。

不新增复杂设置面板，不要求用户选择“纯色模式”。上传同样通过一套规则自动处理。

## 11. 实施拆分与文件范围

| 阶段 | 主要工作 | 阶段完成条件 |
| --- | --- | --- |
| A：建立新契约 | 冻结 0.5；建立区域／事件两层结构与纯色反例测试 | 纯白目标写成可运行失败测试；历史快照保持可复现 |
| B：忠实映射 | 去掉无依据的轮廓与装饰；连续复杂度、边界判定、连音及新节奏预算 | 纯色一个稳定事件；渐变不被吞并；周期结构有依据地重复 |
| C：全链路接入 | 长音包络、条件伴奏、高亮、点击试听、续播、导出与指纹 | 全部区域可追溯，实际播放／导出与事件一致 |
| D：校准与发布本地版本 | 扩展反例、跨环境快照、真实音频对照、安全检查、更新文档 | 所有硬约束通过，参数冻结，版本清晰；不在线发布 |

预计涉及：

- `dist/image-analysis.js`：复杂度、边界及周期支持特征。
- `dist/music.js`：特征目标、可变事件数、连音与条件伴奏；移除强制高潮和模板补全。
- `dist/rhythm.js`：面向实际片段的时间预算，不再要求 120 次起音。
- `dist/audio.js`：持续包络、跨小节事件、长音途中接续与停止清理。
- `dist/app.js / dist/index.html`：区域索引、声音事件索引及文案分离。
- `dist/timing.js`：优先复用现有转换；如需修改，必须维持所有消费者共用时间轴。
- `tests/`：新增忠实性、合并、长音与新接口测试；保留旧版本基线而非篡改历史结果。

不是小改几个评分权重即可完成。主要风险是区域与事件一对一假设渗透在播放、点击、指纹和测试中；这些接口必须一起迁移。

## 12. 验收：纯白是硬约束，但不能只会处理纯白

### 12.1 纯色反例

对精确纯白、纯黑、多档纯灰、纯红／绿／蓝等输入，要求：

- 空间复杂度为 0；全部区域有映射且次序正确。
- 默认主声部实际起音次数为 1、音高种类为 1、内部音高转折为 0。
- 没有内部重新起音、显式呼吸休止、和声进行或固定段落变速。
- 只有全局起止包络；低音／铺底事件为 0。
- 同一颜色改变文件名或尺寸后，只要规范化像素相同，乐谱不变。
- 不同纯色可以有不同基本音高或声音参数，不要求各自演奏不同节奏。

纯白只是最容易观察的样例，不在算法中写 `if (white)` 绕过其他低信息图片。

### 12.2 结构与连续性

在现有 60 张测试图之外补充纯色、近纯色、带小噪声的纯色、单一色块、逐步渐变及匹配颜色分布的结构／噪声对照，建议总样本至少 80 张，另运行参数扫描。

| 测试情形 | 必须检查 |
| --- | --- |
| 白色与接近白色、小幅解码噪声 | 不因微小噪声重新补出一首歌；音高／节奏可保持相同 |
| 灰阶渐变及累积微小变化 | 能形成缓慢目标变化与量化平台；不能被相邻容差全部吞并 |
| 纯色底上的明显小色块 | 局部真实变化保留，不被全局复杂度均值压掉 |
| 相同平均色的条纹／棋盘 | 内部结构仍能提供重复起音依据，不能只看均值 |
| 多个周期／方向的重复结构 | 起音分组确实读了周期与方向，而非统一五音或小节循环 |
| 匹配整体颜色分布的随机噪声 | 不因原始熵高而一味提高起音密度；报告多组固定种子的实际分布 |
| 复杂图与丰富色块图 | 仍有真实音高／节奏差异，不能为了纯白通过而把所有图压成单音 |
| 少量局部编辑、量化边界附近编辑 | 优先影响相关片段；跨全局或分组边界时保留诊断原因 |

检查实际起音数、音高种类／转折、和声更换、重触发证据、持续片段数及来源区域，而不只看完整指纹是否不同。

同一输入重复生成、当前可用浏览器与 Node 的规范化像素结果保持一致；继续使用固定精度与确定性并列决策。回退必须是更简单但仍基于当前图片的构造，不能回退到固定曲子。

### 12.3 播放、安全与本地功能

- 120 个区域的正向与反向引用完整，不重排、不漏区域；多个区域共享事件时每个都可点击。
- 实际事件只排程一次；纯白扫描经过 120 区域不会触发 120 次振荡器攻击。
- 检查跨多小节长音、长音中切换音色、停止再播、休止、尾音及节点清理。
- 所有音色进行真实离线渲染，检查非有限样本、削波、峰值、可听响度、稳定段包络、释放与 WAV 头／长度。
- 高亮、长音续播和导出使用相同时间轴；实测直接本地 HTML 的生成、播放、区域试听及保存。
- 自动化若受 `file://` 限制，报告限制并由实际本地功能检查补充，不用 HTTP 测试冒充文件协议验证。

现有 `tests/score-contract.cjs` 的“120 个主旋律音”“至少四个音高”“唯一高潮”“每句 30 音”等约束只能保留在 0.5 基线测试，不能继续作为 0.6 必须满足的规则。下一版原始多样性总数也不应被当成越多越好，低信息图合理碰撞是允许的。

## 13. 对照工具与验收边界

冻结 0.5 乐谱与对应模块，保留历史 0.3／0.4 资料。新增 0.5 → 0.6 的本地对照，至少覆盖：

1. 纯白：旧版有完整旋律，新版只有稳定持续音，优先听前 10–16 秒。
2. 渐变：检查是否忠实地缓慢变化，是否被合并过度。
3. 条纹／棋盘：检查可测的重复结构是否仍有节奏表现。
4. 丰富图：检查去掉补全后仍有可听的结构，不退化成粗糙噪声。

节奏诊断可固定 88 BPM、同音高、无伴奏，但必须保留“是否重新起音”这一实际差别；不能把新版长音又切成旧版的 120 个音来比较。正式比较另外恢复各自图像速度、音高与实际包络，并同时展示来源映射。

响度匹配仅用于公平对照，不改写正式作品参数。用户主观评分仍不是实施前提；不能把自动结构与音频安全检查称作听感已经通过。

本文是待实施计划，没有执行 0.6 测试，也没有声称上述目标已实现。下一步完成数据契约与反例测试后，再开始修改生成器及播放链路。

## 14. 首版不做什么

- 不引入 AI、物体识别、情绪推断或在线音乐生成。
- 不把全图哈希变成随机旋律种子，不追求任意两图绝不撞谱。
- 不增加鼓组、混合拍子、区域内多音扫描、复杂编辑器或用户调参面板。
- 不在本轮顺带改变整曲长度、规范化分辨率或图片读取路径。
- 不为让纯白图“好听”再加一套白图专属主题或固定和弦。
- 不删除历史算法与验证记录，不在线发布。

## 15. 完成后的产品判断

**纯白图应听起来像一个稳定的声音，而不是一首被白色触发的预设小曲。**

从纯色到渐变，再到重复纹理和复杂图，音乐应随真实结构逐步变丰富。能听出图片的变化程度与组织方式，并且能追溯声音来源，比让所有输入都出现同样的音乐剧情更重要。
