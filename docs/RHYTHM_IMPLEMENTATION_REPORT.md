# 图鸣 · PixelMusic 0.5 节奏优化实现报告

日期：2026-10-05  
版本：作曲／合成 0.5.0；空间节奏 `spatial-rhythm-v1`  
结论：图片现在实际影响起音、时值、停顿、密度、速度及伴奏，而非只在同一套节奏上换音高。本轮不发布在线预览。

仍保留 24 列 × 5 行的蛇形逐音顺序，五行不是同时奏响的和弦；120 个区域每个保留一个主旋律发声事件。全曲仍为四拍子、16 小节、64 拍，不使用图片语义识别、AI 音乐模型、在线音源或上传服务。

## 2. 具体音乐行为

`dist/image-analysis.js` 在原像素规范化与颜色统计之外补充空间结构；`dist/rhythm.js` 负责图片节奏计划；`dist/music.js` 再按生成的拍位搜索音高并安排伴奏。

- 平滑或稳定结构倾向低速度、较多留白与延长落点。
- 有组织的变化参与密度分配与动机，不把原始边缘数量直接当作“越多越快”。
- 局部显著转折参与强拍和长音评分；并非一律加快。
- 保留图内关联与四句发展，不要求每个小节都陌生，也不随机挑选整曲模板。

名义时值使用 0.25、0.5、0.75、1、1.5 拍，最多连续三个最短音。每小节至多一段显式休止、上限 0.75 拍；休止可在开始、中间或末尾，首小节保留清晰起音。句末音至少 0.75 拍，整曲末音至少 1 拍。实际包络按连奏、重复音、较大跳进和句尾分别处理，不越过计划的休止。

低音每小节 1–2 个结构性支点，不逐音复制旋律；铺底可合并相同和声，在有组织的活跃纹理中有限拆分。晚段句末休止允许全体收气，其他休止仅让主旋律呼吸。未加入鼓组、三连音、混合拍子或额外环境音乐模式。

## 3. 速度和统一时间轴

全局速度使用固定标定的空间活动度，而非只看亮度。理论范围 76–104 BPM；当前 60 图实际为 76、78、80、82、84、86、88、90、92、94 BPM，不能把理论上限写成已测覆盖。

`dist/timing.js` 对“每拍秒数”分段线性插值并解析积分，提供 `beatToTime()`／`timeToBeat()`。乐句速度偏移限制在约 ±3.5%，终点降至基础 BPM 的 94%；这是结构化呼吸，不按每个像素突然变速。固定速度诊断使用 `tempo:false`。

主旋律、低音、铺底均分别转换起点和终点；扫描、高亮、续播、总时长和离线渲染使用同一累计时间轴。回声延迟固定为基础速度的 0.75 拍，明确不随微小速度呼吸不断重调。

本轮新版完整表达离线音频实际约 43.11–52.82 秒，含尾音与渲染预留；不是所有图片都固定同一时长。

用 256 格拍点网格上的起音集合计算 Jaccard 距离：0 表示起音位置相同，越大表示差异越大。

| 对照 | 起音距离 |

三组明确不同结构的距离均超过本轮工程门槛 0.20，相似局部编辑保留大部分起音关系。部分图仍有相同节奏：既不强制“每图一个 BPM”，也不承诺任意两图永不撞谱。门槛是本轮测试集上的工程检查，不是音乐质量定律。

## 5. 局部变化、确定性和回退

四个受控小编辑分别位于第 2、8、14、20 列：对一个区域 RGB 各增加 5，在全局调式、速度、主题和节奏动机不跨边界时，各自只影响所在乐句中的 3 个音高／力度事件。

原夕阳局部对照跨过一个已记录的全局色彩锚点量化边界，允许节奏动机出现少量其他乐句变化；音高／力度变化按四句统计为 `[0,4,4,0]`，起音距离仍仅 0.065。诊断保留锚点及边界余量，不能宣称任何局部编辑都只改一个音或永远不影响全局。

搜索采用固定候选顺序和并列决策；节奏约束无合法候选时以简化评分、取消该小节休止重新构造，记录 `rhythmSimplifiedBars`，不偷偷退回一套所有图共用的节奏。强制节奏简化及音高回退路径均验证确定性与合法性。

跨环境核对曾发现极小浮点差异可影响完整指纹，现将搜索累计评分固定到 1e-8 精度、实际发声的时长／力度等参数固定到 1e-6 精度。最终 60 张相同规范化像素的真实 Chromium 乐谱快照与 Node 完整乐谱指纹逐一一致，覆盖音高、节奏、演奏、伴奏及速度时间轴。

约定仍是“相同规范化像素、作曲版本和设置 → 相同乐谱”。这次只验证了当前 Chromium 与 Node，不代表所有浏览器都已实测。不同解码、缩放和色彩管理仍可能生成不同像素；不保证最终 WAV 字节跨浏览器相同。摘要不是密码学哈希。
