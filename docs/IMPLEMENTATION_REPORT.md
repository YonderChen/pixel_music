## 2. 模块与确定性边界

主页面使用普通相对路径脚本，无打包依赖、ES module 导入、网络请求或运行时音频资源下载。规范化版本为 `canvas-cover-rgba-v1`，作曲／音色版本为 `0.4.0`。旧版 `legacy` 分支保留原调式、主音、速度和编曲用于金标准回归；盲听时只把旧版 BPM 对齐新版，以便比较。

确定性承诺只针对相同规范化 RGBA 像素、算法版本与设置产生相同乐谱事件；最终浏览器图片解码、缩放、色彩管理、音频渲染仍可能不同。图像及事件摘要为自定义非密码学摘要，不承诺数学上的一图一首绝不碰撞。

全图调式、主音、和声或量化主题的阈值附近仍可能出现全局变化。四拍粒度的速度选择、低饱和色相抑制、局部区域种子改善了受控样本稳定性，不能据少量测试声称任意编辑都只改变一个音。

- 试听统计另有纯函数单元检查：每张图分别要求暖键的短片段／完整曲覆盖，重复同图不能填补其他图；揭晓后的记录、其他音色及无效数据不进入第一轮盲听门槛，偏好／中位数／图片关联与设备覆盖分别核对。测试分数全部是独立合成数据，没有写入页面、导出为用户评价或作为主观验收证据。

## 5. 真实试听交接

打开 [tests/listen.html](../tests/listen.html)，先用“夕阳＋暖键＋前 16 秒”生成 A／B／C；先试听、评分，再揭晓。然后选完整曲目听主题回应、中段高潮与收尾。每轮会重新排列版本，不要凭上一轮的字母推断版本。

反馈最有用的格式：图片／音色、片段或完整曲、最喜欢的版本、听感问题及大约发生时间。例如“夕阳，暖键，完整 B，25 秒附近跳得突兀”——这是格式示例，不是已收集的评价。若愿意量化，可用五项评分并导出 JSON；评分只存在本页内存，刷新／关闭前请导出。

用户后来明确选择跳过其主观评分等待，以开发者的旋律、节奏与演奏取舍定稿。这里的完整盲听现在为可选后续试验，不是本轮完成条件。方案中“新版偏好约 70%、好听程度中位数提高至少一分、图片关联不下降”的真人门槛未被测量，也没有用合成数据宣称它通过。

## 6. 最终音乐取舍与完成审查

选择当前暖键版本作为默认，定位为轻柔、可哼唱的器乐小品。A 与 A′ 共用主要节奏骨架，A″ 在主题归来后延长终止音；B 提升音区并集中一次主要高潮。保留主题的重复与局部变化，不再为追求更多变化而增加跳跃、加速或持续效果器。

十二张测试图中，同音或三半音以内的相邻连接占 85.7%–95.8%，最长连续同音为三个事件，旋律音域为十四半音。这些是支持当前取舍的乐谱观察：整体平稳、少量表达性跳跃、明确中段峰值；不是自动“好听分”。图像继续决定主题细节、乐句变奏和表达，同图复现及四处局部变化检查均通过。
